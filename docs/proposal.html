Decision 1

Build it on Ready4AI

Ready4AI already has the hard, risky parts, and they are tested: teacher sign-up, class codes and passcodes, each school's data kept apart by the database, the daily clean-up, export and delete, the rule that stops pages contacting other sites, hosting on Render, and the privacy paperwork. A separate site would mean writing and testing all of that a second time, and keeping two copies in step for ever. A teacher would also need a second account.

On Ready4AI a course is a folder of pages plus one server module. Packet Express is already laid out that way, so this course copies its shape.

  • One course, three grades. A teacher picks the grade when they make a class, as in Packet Express. One name, one game world, one set of teacher pages.
  • Where the work happens. The lessons, labs and tests are written in this repository so the course can be run and checked on its own. The Ready4AI side is a small branch that adds the course folder and its server module. I can read Ready4AI from here but not save to it, so I will ask for that access when the course is ready to plug in. Nothing goes to the live site without your say.
  • One thing the platform does not have yet. These lessons are checked by running the student's code. Pixel Trail's server only reads code, it does not run it. I will add a locked-down, time-limited runner on the server for this course and write tests that attack it.
Decision 2

JavaScript, with a ramp for sixth graders

  • It runs at once on a Chromebook. Python in the browser is a download of several megabytes before the first line runs, on every device.
  • It reuses Pixel Trail's locked-down sandbox and its error explainer, which already turns error messages into sentences a beginner can act on.
  • The server can rerun the same checks, so nothing the browser reports has to be trusted.
  • It matches the Ready4AI plan, which keeps Python for the micro:bit course.

The ramp. Grade 6 never starts from an empty editor: students fill gaps, change one value and run it, and pick the right line from three. Grade 7 gets starter code and writes one short function at a time. Grade 8 writes whole functions, writes tests for them, and reads code someone else wrote.

Decision 3

Name and game

A quick web search found no cybersecurity or school product using any of these three names. That is not a trademark clearance; a proper search is still needed before you sell under the name. None uses a name on your avoid list.

My pick

Cipher City

Story
A neon city has gone dark. Students are its new security crew.
Class map
The skyline. Each finished lesson switches on one building, and the whole class lights the city together. Each grade is a district.
Character
An operator with unlockable visors, jackets and keyboards, plus a collectable sidekick bot for each badge.
Reward game
Night Shift: bounce bad packets away from the city gate.

Glitch Guard

Story
You look after an old arcade. Mischievous Glitches keep getting into the machines.
Class map
The arcade floor. Each lesson powers on one cabinet.
Character
The Glitches themselves: catch one per lesson and collect the set.
Reward game
One of the cabinets opens for play.

Patch Crew

Story
A giant old school computer is full of holes. Your crew patches them.
Class map
A circuit board that fills in, one chip per lesson.
Character
A crew of small repair bots you unlock and upgrade.
Reward game
Bug Hunt: a maze chase through the circuits.

I prefer Cipher City because a city gives three districts for three grades and a map the whole class can watch grow on the projector. I looked at Neon Vault too and dropped it: there are many registered game names starting with Neon.

The look

Friendly shapes, arcade glow, readable first

The same lesson screen in the three color settings a student can choose. Body text is a plain rounded font in near-white or near-black. The blocky arcade lettering is only for the logo and small labels, and the code font is only for code. Glow and scan lines belong to the arcade setting and switch off with less motion and high contrast. All artwork is original, and the fonts are the ones Ready4AI already serves from its own site.

Arcade (the default)

Off-white text on deep navy, not green on black. Green and amber are for accents and code.

Daylight

Your light theme. The code window stays dark so it still feels like a terminal.

High contrast

Black, white and yellow only. No glow, no scan lines.

Decision 4

The 30 lessons

Each grade stands alone, so a school can start in any year. Every lesson follows your fixed arc: mission, build steps, quick check, then turn in with a written reflection. Every lesson has code, and every target is pretend and lives inside the page. Standards are Massachusetts DLCS codes; the lesson pages and the coverage page will quote each one word for word.

Packet Express grade 8 already teaches threats, passwords, ciphers, HTTPS, firewalls and ethical hacking by sorting, matching and working a cipher by hand. These lessons do not repeat that. Here students write the program: the checker, the cracker, the rules.

Held in every lesson

Safety rules

  • Every target is a pretend one built into the page. No lesson can scan, probe or send anything to a real system, and no real attack tool or working exploit appears.
  • Student code runs in a locked-down frame with no network access. Tests will prove it cannot reach out.
  • Every password box says "Use a made-up password. Never type a real one." No real personal details in any example.
  • Permission, the law and reporting what you find come up in every lesson's mission and reflection, with a security job named in each.
  • Phishing, tricks and unkind messages are written so the person who was targeted is never blamed. Those lesson plans carry a teacher note on what to do if a student tells you something happened to them.
